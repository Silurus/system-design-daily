# System Design Daily

Ежедневный разбор одной темы по System Design. Уровень: собеседование Senior.

## Формат занятия
1. Повторение: вопросы по прошлым темам из [REVIEW.md](REVIEW.md), где ответ был неполным. Каждый раз в новой формулировке — чтобы не заучить, а понять.
2. Короткая теория с примером из реальной системы.
3. Вопросы и обсуждение в диалоге.
4. Задача по теме — отложена, пока не попросит Максим.
5. Конспект фиксируется в `topics/NN-slug.md`.

## Слабые места и ворота
[REVIEW.md](REVIEW.md) — вопросы по темам с неверными или неполными ответами. Пункт закрывается, когда ответ верный и полный два раза подряд в разных формулировках.

**Новая тема не начинается, пока не закрыты все открытые пункты.** Пока очередь не пуста, занятие состоит только из повторения. Так слабые места не накапливаются.

## Структура конспекта
- **Суть** — что это и зачем, в 3–5 предложениях.
- **Как работает** — ключевые механизмы.
- **Trade-offs** — что выигрываем и чем платим.
- **Схема** — Mermaid-диаграмма.
- **Пример** — где применяется в реальных системах.
- **Код** — не обязателен. Если без него не объяснить (или это шпаргалка по алгоритму) — на C#.
