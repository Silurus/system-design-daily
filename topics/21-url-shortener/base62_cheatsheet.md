# Шпаргалка: Система счисления Base62

Краткое руководство по прямому и обратному переводу чисел в 62-ричную систему (используется для сокращения URL).

## Алфавит системы
`0-9` (0–9), `A-Z` (10–35), `a-z` (36–61). Всего **62 символа**.

## Отличия от Base64

Названия похожи, но это разные алгоритмы для разных задач.

### Главное — как устроен алгоритм
- **Base64 режет биты.** 64 = 2⁶, поэтому каждый символ — ровно 6 бит. Берём 3 байта (24 бита), режем на 4 куска по 6 бит, каждый кусок → символ. Никакой арифметики, только сдвиги и маски, работает потоком на данных любой длины.
- **Base62 делит число.** 62 — не степень двойки, на целое число бит символ не ложится (log₂62 ≈ 5,95). Поэтому биты нарезать нельзя — приходится делить с остатком на 62, как в примере ниже. Это перевод **числа** в другую систему счисления, а не перекодировка байтов.

### Сравнение

| Параметр | Base62 | Base64 |
|---|---|---|
| Вход | Число (ID, счётчик) | Произвольные байты |
| Алгоритм | Деление с остатком на 62 | Нарезка по 6 бит (3 байта → 4 символа) |
| Алфавит | `0-9A-Za-z` | `A-Za-z0-9+/` и `=` для дополнения |
| В URL | Безопасен, экранировать нечего | `+` и `/` надо экранировать; есть вариант Base64url с `-` и `_` |
| Дополнение `=` | Нет | В стандартном Base64 есть, длина кратна 4 |
| Длина результата | Зависит от величины числа | Зависит только от числа байтов: `⌈n / 3⌉ × 4` |
| Стандарт | Нет единого: порядок символов в алфавите у всех свой | RFC 4648, одинаково во всех языках |
| Где применяется | Короткие ссылки, публичные ID | Вложения в email, бинарные данные в JSON, Data URL, JWT (Base64url) |

### Пример на одном и том же ID = 125191

```csharp
Base62.Encode(125191);                                     // "WZD"      — 3 символа
Convert.ToBase64String(BitConverter.GetBytes(125191));     // "B+kBAA==" — 8 символов
Convert.ToBase64String(BitConverter.GetBytes(125191L));    // "B+kBAAAAAAA=" — 12 символов
```

Base64 кодирует не число, а его байты в памяти: `int` — это 4 байта `07 E9 01 00`, `long` — 8 байтов. Поэтому результат зависит от типа и порядка байтов, содержит `+` и `=` и длиннее. Base62 кодирует само значение и не тащит лишние нулевые байты.

**Вывод для URL shortener:** Base62 — для превращения ID в короткий код. Base64 — когда нужно передать бинарные данные через текстовый канал.

---|---|---|
| **Алфавит** | 62 символа: `0-9A-Za-z` | 64 символа: `A-Za-z0-9+/` (плюс `=` для padding) |
| **Что кодируем** | **Число** (ID, счётчик) | **Байты** (бинарные данные, строки) |
| **Применение** | Короткие ID, сокращённые URL | Передача бинарных данных в текстовом виде (email, JSON, XML) |
| **URL-безопасность** | Да (все символы допустимы в URL без экранирования) | Нет: `+` и `/` требуют экранирования; есть вариант Base64url с `-_` |
| **Padding** | Не нужен | Обязателен (`=` добавляется, чтобы длина была кратна 4) |
| **Длина результата** | Зависит от величины числа (переменная) | Фиксированная формула: `⌈(n_bytes × 4) / 3⌉` |
| **Обратимость** | Однозначная: один короткий код → одно число | Однозначная: одна Base64-строка → один набор байтов |

**Пример:**  
- `Base62.Encode(125191)` → `"WZD"` (3 символа)
- `Convert.ToBase64String(BitConverter.GetBytes(125191))` → `"1+cBAA=="` (8 символов, содержит `+` и `=`)

**Вывод:** Base62 для чисел короче и чище в URL, Base64 — универсальный способ представить любые данные в ASCII.

## 💻 Функции на C#

```csharp
public static class Base62
{
    private const string Alphabet = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz";
    private const int Base = 62;

    /// <summary>Прямой перевод: Число (ID) → Короткий код</summary>
    public static string Encode(long num)
    {
        if (num == 0) return Alphabet[0].ToString();
        
        var result = new System.Text.StringBuilder();
        while (num > 0)
        {
            result.Insert(0, Alphabet[(int)(num % Base)]);
            num /= Base;
        }
        return result.ToString();
    }

    /// <summary>Обратный перевод: Короткий код → Число (ID)</summary>
    public static long Decode(string code)
    {
        long num = 0;
        foreach (char c in code)
        {
            num = num * Base + Alphabet.IndexOf(c);
        }
        return num;
    }
}
```

## 🧮 Математический пример: Код "WZD"

### 1. Прямой перевод (Деление с остатком)
Переводим `ID = 125191` в Base62:
* `125191 / 62 = 2019`, остаток **13** (`D`)
* `2019 / 62 = 32`, остаток **35** (`Z`)
* `32 / 62 = 0`, остаток **32** (`W`)

Собираем остатки снизу вверх: **`WZD`**.

### 2. Обратный перевод (Схема Горнера)
Вместо вычисления степеней в лоб ($32 \cdot 62^2 + 35 \cdot 62^1 + 13 \cdot 62^0$), код использует **схему Горнера** — последовательный сдвиг разрядов слева направо.

**Пошаговый процесс в цикле (для "WZD"):**
1. **Старт:** `num = 0`
2. **Символ 'W'** (значение 32):  
   `num = 0 * 62 + 32` = **32**
3. **Символ 'Z'** (значение 35):  
   `num = 32 * 62 + 35` = **2019**
4. **Символ 'D'** (значение 13):  
   `num = 2019 * 62 + 13` = **125191**

### 🧠 Почему это работает?
Если раскрыть все скобки финального выражения, мы получим классическую формулу разложения по степеням:
$$\text{ID} = ((32) \cdot 62 + 35) \cdot 62 + 13 = 32 \cdot 62^2 + 35 \cdot 62^1 + 13 \cdot 62^0 = 125191$$
Компьютер считает этот результат за 3 простых умножения и 3 сложения, не выполняя операцию возведения в степень.
